# BPMN — Процесс оформления и доставки заказа

> Диаграмма нарисована в draw.io. Ниже текстовое описание потока.

---

## Участники (Пулы)

- **Покупатель** — мобильное приложение
- **Система FoodRun** — бэкенд
- **Ресторан** — приложение партнёра
- **Курьер** — мобильное приложение курьера

---

## Основной поток (To-Be)

### Покупатель → оформление
1. Выбирает ресторан и блюда, добавляет в корзину
2. Вводит адрес, выбирает оплату
3. Нажимает «Оформить заказ»

### Система → обработка
4. Создаёт заказ со статусом `PENDING`
5. Инициирует оплату через платёжный шлюз
   - ✅ Успешно → статус `PAID`, заказ отправляется в ресторан
   - ❌ Отклонено → уведомление покупателю, заказ `CANCELLED`

### Ресторан → приготовление
6. Получает уведомление о новом заказе
7. Принимает заказ → статус `PREPARING`
   - (если не ответил за 5 мин → автоотмена + возврат)
8. Готовит блюда, отмечает `READY`

### Курьер → доставка
9. Система назначает свободного курьера
10. Курьер принимает → статус `PICKED_UP`
11. Доставляет заказ, отмечает `DELIVERED`

### Завершение
12. Push-уведомление покупателю «Заказ доставлен»
13. Запрос оценки

---

## Жизненный цикл заказа

```
PENDING → PAID → PREPARING → READY → PICKED_UP → DELIVERED
                                               ↘ CANCELLED
```

---

## Edge cases

| Ситуация | Действие |
|---|---|
| Оплата отклонена | Уведомление + отмена |
| Ресторан не ответил (5 мин) | Автоотмена + возврат средств |
| Нет свободных курьеров | Заказ в очереди, покупатель уведомлён |
| Курьер отменил принятие | Назначается следующий |
