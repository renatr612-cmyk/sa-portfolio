# Модуль 1 — Основы системного анализа

## Что такое системный анализ?

Системный анализ — это процесс изучения системы, её компонентов и взаимосвязей с целью понимания требований и разработки решений. Системный аналитик (SA) — связующее звено между бизнесом и IT-командой.

---

## Роль системного аналитика

**Основные обязанности:**
- Сбор и анализ требований от заинтересованных сторон
- Написание технической документации (ТЗ, SRS, BRD)
- Моделирование бизнес-процессов
- Взаимодействие с командой разработки, QA и PM
- Анализ данных и выявление проблем в системе

**С кем взаимодействует SA:**
| Роль | Как взаимодействует |
|---|---|
| Product Manager | Уточнение бизнес-целей и приоритетов |
| Разработчики | Передача требований, ответы на вопросы |
| QA-инженеры | Помощь в написании тест-кейсов |
| Заказчик/Бизнес | Интервью, согласование требований |
| UX/UI дизайнер | Описание пользовательских сценариев |

---

## Жизненный цикл разработки ПО (SDLC)

```
1. Планирование → 2. Анализ → 3. Проектирование → 4. Разработка → 5. Тестирование → 6. Внедрение → 7. Поддержка
```

**Роль SA на каждом этапе:**
- **Планирование:** участие в оценке feasibility, определении scope
- **Анализ:** сбор и документирование требований
- **Проектирование:** участие в разработке архитектуры, прототипов
- **Разработка:** ответы на вопросы команды, управление изменениями
- **Тестирование:** верификация требований, участие в UAT
- **Внедрение:** поддержка перехода, обучение пользователей

## Методологии разработки

### Waterfall (Водопад)
- Последовательные фазы, каждая фаза завершается перед началом следующей
- Подходит для проектов с чёткими требованиями
- SA создаёт полную документацию в начале проекта

### Agile
- Итеративная разработка короткими спринтами (1–4 недели)
- Требования могут меняться
- SA работает с Backlog, пишет User Stories, участвует в спринт-планировании

### Scrum (фреймворк Agile)
**Ключевые роли:**
- Product Owner — отвечает за Backlog
- Scrum Master — фасилитирует процесс
- Development Team — разрабатывает продукт

**Артефакты Scrum:**
- Product Backlog
- Sprint Backlog
- Increment (рабочий продукт)

**Церемонии:**
- Sprint Planning
- Daily Standup
- Sprint Review
- Sprint Retrospective

## Ключевые понятия

| Термин | Определение |
|---|---|
| Stakeholder | Заинтересованная сторона проекта |
| Scope | Границы проекта |
| As-Is | Текущее состояние процесса/системы |
| To-Be | Целевое состояние процесса/системы |
| Gap Analysis | Анализ разрывов между As-Is и To-Be |
| Backlog | Список задач/требований, упорядоченных по приоритету |
| MVP | Минимально жизнеспособный продукт |
| KPI | Ключевой показатель эффективности |
